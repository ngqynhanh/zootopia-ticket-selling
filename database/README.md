# Database

PostgreSQL 16 (14+ works). **The Flyway migrations are the source of truth:**

| File | Content |
|---|---|
| `backend/src/main/resources/db/migration/V1__init_schema.sql` | All tables, constraints, indexes, `updated_at` triggers |
| `backend/src/main/resources/db/migration/V2__reference_data.sql` | Data the app needs: system settings, 13 ticket types, 4 group policies, 11 combos |
| `database/schema.sql` | Copy of V1 + V2 in one file (for graders / manual setup), regenerated by the command below |
| `database/seed-data.sql` | Demo data, 100+ records (week 5) |
| `database/ER-diagram.md` | ER diagram (Mermaid) |

Flyway runs the migrations automatically when the backend starts. **Never edit a migration that has
already been applied**: add a new `V3__...sql` instead.

Regenerate `schema.sql` after adding a migration (Git Bash, from the project root):

```bash
cat backend/src/main/resources/db/migration/V*.sql > database/schema.sql
```

## Schema at a glance

- **20 entity tables + 3 junction tables** (`combo_zones`, `user_promotions`, `user_saved_activities`), far above the 50-column minimum.
- **Audit trail**: `created_at`, `updated_at`, `created_by`, `updated_by` on business tables, plus `audit_logs` (JSONB old/new values).
- **Soft delete**: `is_active` + `deleted_at` on master data (users, ticket types, combos, zones, animals, activities, promotions).
- **Business rules enforced by CHECK constraints**, for example:
  - a group has at least 10 visitors;
  - one guide serves at most 50 visitors;
  - a QR scan admits 1–4 people;
  - `total_amount = subtotal - discount_amount`;
  - an order item is either a ticket type or a combo;
  - uploads are at most 5 MB and only jpg/png/webp/pdf.
- **Cascades**: deleting an order removes its items, tickets, payments and group details. Ticket types, combos and zones that orders still use can't be hard-deleted (`RESTRICT`), so they are soft-deleted.
- **Justified denormalization**: `order_items.unit_price` / `line_total` snapshot the price at purchase time, because catalog prices change later.
- **Indexes**: every foreign key (checked by `SchemaMigrationTest`), plus composite indexes for dashboards (`orders(status, created_at)`), partial indexes for the scheduled jobs, and a GIN full-text index on FAQs.
